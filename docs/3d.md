# Escritório 3D

O escritório 3D é uma **segunda forma de desenhar o mesmo escritório**. Ele não tem simulação própria: usa a mesma
`Sim` do 2D (`client/src/world/sim`), que recebe os snapshots do servidor e decide salas, caminhos, assentos, vida
social e o estado de cada personagem. O 3D só transforma esse estado em cena, câmera e entrada, e implementa o mesmo
contrato que a UI já usa (`client/src/world/api.ts` → `WorldApi`). Por isso a UI, o store, a cidade, o timelapse, os
pedidos de permissão, as mensagens e as métricas funcionam sem mudança.

```
servidor (sources/ claude, codex) ──snapshot──▶ OfficeStore ──▶ Sim (world/sim) ──▶ world3d (Three.js)
                                                                              └──▶ world (2D, pixel art)
UI (client/src/ui) ◀── WorldApi ──▶ um dos dois mundos
```

## Usar

- Por padrão nesta branch o escritório abre em 3D. **Configurações › Visual › Visão do escritório** troca para o 2D
  (fica guardado no navegador); `?view=2d` ou `?view=3d` na URL fazem o mesmo. Sem WebGL2, abre no 2D.
- **Qualidade gráfica** (Baixa, Média, Alta, Ultra) fica no mesmo grupo e vale na hora.
- Mouse: arrastar com o botão esquerdo move, botão direito (ou Shift + esquerdo) gira, roda aproxima no ponto do
  cursor. Clique seleciona um agente ou uma sala; duplo clique foca e segue. Botão direito sem arrastar numa sala abre
  o menu de renomear (como no 2D).
- Teclado: WASD/setas movem, Q/E giram, +/- aproximam, **F** segue o selecionado, **0** volta à visão geral.

### Editor de personagem 3D

No lápis **Editar personagem** da gaveta do agente (o mesmo do 2D), com o mundo em 3D, aparece o bloco **Aparência
3D**: prévia girável (arrastar/setas) com zoom (roda/+/-) e animação de prévia, personagem-base (12 modelos), cores
das regiões do atlas (cabelo, pele, roupa, calça/saia, calçados — rótulos por heurística de altura e tom de pele),
acessório (óculos, óculos escuros, boné, gorro, fone, laço) com cor, identificação profissional (aparece na etiqueta)
e **Restaurar padrão 3D**. O nome continua indo para o servidor pelo editor de sempre; a aparência 3D vale ao
**Salvar** e fica no navegador (`localStorage`, chave `habblaud.3d.looks.v1`), indexada pela semente do personagem do
projeto — a próxima sessão na mesma sala chega com ela. Tudo o que vem do armazenamento é validado (`looks.ts:
sanitize`).

### Windows

Testado no Windows 11 com Node 24 (`npm ci`, `npm run dev`): o servidor achou as sessões do Claude Code em
`C:\Users\<você>\.claude` e o Codex em `C:\Users\<você>\.codex` sem WSL. Para rodar:

```powershell
npm ci
npm run dev
```

e abrir `http://127.0.0.1:4747`. O script `npm run demo` usa a sintaxe `VAR=1 comando` do bash e **não** funciona no
PowerShell; use `$env:HABBLAUD_DEMO=1; npm run dev`. Só o cliente com dados fictícios: `npm run dev:client` e
`http://localhost:5173/?mock=1`.

## Código (`client/src/world3d`)

| Arquivo | O que faz |
|---|---|
| `index.ts` | `createWorld3D()`: liga simulação, palco, prédio, avatares, etiquetas, câmera e entrada; implementa `WorldApi` |
| `stage.ts` | renderizador, céu e sol pela hora, sombras, GTAO, tone mapping, presets de qualidade |
| `camera.ts` | câmera estratégica (órbita em volta de um alvo no chão), transições, margens da UI |
| `building.ts` | prédio a partir do layout da simulação: pisos, paredes com recorte, portas, itens de parede, área externa |
| `furniture.ts` | móveis e itens de parede modelados com peças arredondadas; telas dos monitores |
| `kit.ts` | paleta, materiais e geometrias compartilhados; `mergeStatic` (funde a geometria estática por material) |
| `assets.ts` | catálogo dos personagens Gobkit, biblioteca de clipes com retarget por índice de osso, kit de natureza |
| `characters.ts` | um avatar por personagem: posição suavizada, rotação, altura do assento, crossfade, item na mão, anel |
| `anim-map.ts` | pose da simulação → clipe (puro, com testes) |
| `screens.ts` | atividade real do agente → o que o monitor da mesa mostra |
| `labels.ts` | nome e balão sobre a cabeça (mesmas regras do 2D) |
| `looks.ts` | aparência 3D por personagem (modelo, cores do atlas, acessório, identificação), validação, regiões |
| `accessories.ts` | acessórios modelados no tamanho da cabeça de cada modelo, presos ao osso da cabeça |
| `editor.ts` | editor da aparência 3D (prévia própria, escolhas, salvar/restaurar) montado no editor da gaveta |

### Decisões

- **Three.js puro, sem React Three Fiber.** O cliente do Habblaud é TypeScript sem framework e o contrato do mundo é
  imperativo (`select`, `focusAgent`, `setOptions`...). Colocar React só para o canvas duplicaria o ciclo de vida e
  não resolve nada que falte aqui. `three/addons` cobre GLTF, `SkeletonUtils`, pós-processamento e
  `BufferGeometryUtils`.
- **Sem Rapier e sem NavMesh.** A simulação já tem a grade caminhável, o A\*, a reserva de assentos e o desvio de
  quem anda junto; o 3D desenha exatamente esses caminhos. Uma segunda navegação 3D divergiria da simulação (e do 2D).
  Física e NavMesh entram quando houver primeira/terceira pessoa (Fase 6), para o avatar do usuário.
- **Sem Zustand.** O estado já mora no `OfficeStore` e na `Sim`.
- **1 tile = 1 unidade 3D.** As coordenadas do layout viram cena direto (`x/16`, `y/16`), então qualquer sala nova do
  layout aparece em 3D sem código novo.
- **Personagens Gobkit.** A família inteira usa o mesmo esqueleto de 13 ossos; o pack de escritório (Vol.2) traz 28
  clipes nomeados. Eles viram uma biblioteca aplicada a todos os modelos (só rotações, e a translação do quadril
  escalada pela proporção do alvo). Origem e licenças: `client/public/assets/3d/ASSETS.md`.
- **Móveis próprios.** Geometria arredondada com uma paleta única, para os móveis combinarem com os bonecos e não
  dependerem de pacotes com licenças diferentes.

## Prédio

O prédio é o mesmo layout da simulação (`client/src/world/layout`), então qualquer sala vale para o 2D e o 3D e é
usada de verdade pelos agentes. O núcleo tem 3 colunas (`CORE_COLS`): recepção (elevadores) e banheiros; copa e
lounge; biblioteca e sala de reuniões. Depois vêm as salas de projeto (uma por projeto aberto), o corredor, as vagas
vazias com pátio e a área externa (gramado com tufos e juncos Gobkit, árvores, calçada e rua). A vida social escolhe
lugares pelo tipo (estante, janela, poltrona, roda de conversa), então as salas novas entram nos passeios sem regra
nova.

## Ferramentas de agentes

| Ferramenta | Como entra | Mensagens | Observações |
|---|---|---|---|
| Claude Code, Codex | fontes originais do Habblaud (sem mudança) | como antes | — |
| OpenCode | `server/sources/opencode` (PR #211): lê o `opencode.db` só para leitura | não | permissões do OpenCode não ficam no banco |
| Modelos locais | `server/local-agents`: o próprio servidor roda a conversa com o Ollama/LM Studio | sim | ferramentas só de leitura, presas à pasta |

**Agentes locais** (`server/local-agents`): `llm.ts` fala com o Ollama (`/api/chat`, `/api/tags`, `/api/ps`) e o LM
Studio (`/v1/*`), só por endereços de loopback; `tools.ts` oferece `list_dir`, `read_file` (até 12 KB) e `search`,
com `realpath` contra a raiz do projeto (nada de `..`, caminho absoluto ou link para fora); `runtime.ts` guarda as
sessões, limita a 1 turno rodando por vez (os outros esperam na fila), 12 rodadas de ferramenta por turno, aborta no
"Interromper", ajusta a conversa ao contexto (`HABBLAUD_LOCAL_CTX`, padrão 8192 — o padrão do Ollama, 4096, cortava o
prompt de sistema) e grava a transcrição no formato do Claude Code (o terminal do escritório a abre). O prompt de
sistema trata o conteúdo dos arquivos como dado, nunca como instrução. As rotas `/api/local-agents` usam a trava do
"Novo agente" (só pelo próprio computador, JSON obrigatório); mensagens entram pelo registro de mensagens de sempre.
O Habblaud World recebe só agentes do Claude Code e do Codex (`shared/world/projection.ts`, com teste).

## Pendências conhecidas

- **Andares.** A simulação é de um andar só; vários andares exigem caminhos entre andares na simulação e cuidado com o
  que vai para o Habblaud World (o número de andares é dado verdadeiro, ver `CLAUDE.md`). Os elevadores já funcionam
  como entrada e saída (fila, portas animadas).
- Salas de design, pesquisa e escritório administrativo não existem como salas próprias: cada projeto tem a sua sala
  de trabalho, sorteada entre variações. O tema sazonal (Natal/Halloween) ainda não é desenhado no 3D.

- Expressões faciais: os rostos Gobkit são pintados no atlas (sem blendshapes); a expressão vem do corpo (clipes).
- A aparência 3D fica só neste navegador (não vai para o servidor nem para outros aparelhos).
- Os rótulos das regiões de cor são heurísticos; alguns modelos usam a mesma cor em partes diferentes.
- Clipes sem equivalente direto usam o mais próximo (beber café, ping-pong, jokenpô); não há clipe de sentar/levantar:
  a transição é um crossfade curto.
- Pés deslizam um pouco: a simulação anda a 3,2 tiles/s e o clipe Walk vai até 2,4× de velocidade.
- Os GLB do pack de escritório trazem os 28 clipes cada (~6,8 MB no total); dá para enxugar com glTF Transform.
- Sem andares/elevador funcional em 3D além das portas (a simulação ainda é de um andar), sem primeira/terceira
  pessoa, sem NPCs ambientais, sem áudio próprio do 3D (usa as dicas de som do 2D).
- Conectores novos (OpenCode, agentes locais com Ollama/LM Studio) não fazem parte desta fase.
